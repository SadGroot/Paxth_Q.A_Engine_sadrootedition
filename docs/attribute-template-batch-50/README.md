# Fifty additional attribute-set mappings

This batch is included in [the full 138-set manifest](../attribute-template-all/README.md). Use `--all` to fill missing configuration across every backend set while preserving existing rules and headers; `--batch-50` still addresses only this subset.

This batch adds **50 new attribute sets**, **2,195 exact output headers and per-header filling rules**, and **51 illustrative product rows** from `OneDrive_2_10-15-2026`. With the [original pilot](../attribute-template-pilot/README.md), coverage is **55 sets and 2,432 header/rule entries**.

The selection is the first 50 alphabetically among single-sheet workbooks with valid exact headers, usable sample products, an exact existing backend name match, and empty saved rules, headers and classifications. Existing configured sets are preserved. Duplicate/padded headers, unmatched filenames, header-only sheets and unreviewed multiple-sheet files are outside this batch.

Samples establish formats, not factual defaults. The documents cover exact units, spacing, number layouts, dimension axes/separators, keyword/list separators, paragraph structure, title limits and column-aligned bullet priorities where demonstrated. Missing examples and ambiguous mandatory-list annotations are disclosed. Mandatory/optional IDQ classifications are not inferred.

All headers are on row 2. Sample products are on row 3; Vacuum Cleaners also has a real second example on row 4. Its bullet guidance starts on row 5. Product-looking mandatory-field lists are metadata, not additional samples. Rules use both Vacuum Cleaner examples without forcing their differing ml/L unit scales into a universal default.

## Preview and save

The existing importer handles this explicit batch; the original command without `--batch-50` still handles only the five pilot sets.

```sh
npx tsx scripts/import-attribute-template-pilot.ts --batch-50
npx tsx scripts/import-attribute-template-pilot.ts --batch-50 --apply
```

The importer validates the complete fifty-set list and every header/rule before a single transaction. It refuses to overwrite differing saved rules, headers or classifications, backs up the prior rows to ignored `backups/attribute-template-batch-50-*.json`, preserves IDs/names/classifications, and verifies persistence with a fresh read. Identical repeats change nothing. Sample products are never inserted into the catalog.

The review preview is `.cache/attribute-template-batch-50/preview.json`. The format-check workbook is `.cache/attribute-template-batch-50/format-check.xlsx`; it contains original illustrative examples, not generated or verified product content.

## Checks

```sh
npx tsx scripts/import-attribute-template-pilot.test.ts
npm run lint
```

Checks cover all 55 sets: exact ordered headers and one filling-rule section per header, documented unknown formats, observed unit/layout examples, sample isolation, Catalog prompt wiring, protected identifiers, missing-value warnings and Excel round trips. Setting `TEST_DATABASE_URL` also tests each complete batch in a temporary isolated schema: atomic updates, backup failures, overwrite protection, unchanged IDs/classifications, unrelated rows and idempotency. Test schemas are removed afterward.

No live LLM generation or product-fact accuracy checks are part of this format-mapping batch. IDQ still needs explicit mandatory/optional classifications before these sets can run through IDQ.
